# СТАНДАРТ СПЕЦИФИКАЦИИ ЯЗЫКА ПРОГРАММИРОВАНИЯ БЛЯДОКОД (BLYADOCODE)
**Версия спецификации:** 1.0.0-STD  
**Статус:** Нормативный документ (Normative Standard)  
**Классификация:** Троичный структурный экзотерический язык, эквивалентный универсальной машине Тьюринга  

---

## 1. Введение и математические основания

### 1.1. Алгебраическая модель
Язык БЛЯДОКОД базируется на конечной троичной морфологической структуре. Алфавит языка определяется прямым произведением пространств корней и окончаний:

$$\mathcal{L} = \mathcal{R} \times \mathcal{A} \cong \mathbb{F}_3 \times \mathbb{F}_9 \cong \mathbb{F}_{27}$$

где:
* $\mathcal{R} = \{0, 1, 2\}$ — трёхэлементное множество лексических ядер (корней);
* $\mathcal{A} = \{0, 1, 2, \dots, 8\}$ — девятиэлементное множество деривационных аффиксов (окончаний).

Каждый атомарный токен языка представляет собой однозначный элемент множества $\mathcal{L}$, состоящего ровно из $27$ канонических словоформ закрытого словаря.

### 1.2. Вычислительная универсальность
Вычислительная система языка изоморфна классу автоматов с линейной памятью и эквивалентна классической машине Тьюринга над лентой в кольце вычетов $\mathbb{Z}/256\mathbb{Z}$. Следовательно, язык БЛЯДОКОД является вычислительно полным по Тьюрингу (см. Раздел 9).

## 3. Архитектура виртуальной машины

Состояние машины в дискретный момент времени $t \in \mathbb{N}_0$ определяется кортежем:
$$\mathcal{S}_t = \langle \mathcal{T}_t, P_t, PC_t, \Sigma_{loop}, \mathcal{I}_t, \mathcal{O}_t \rangle$$

### 3.1. Память (Лента $\mathcal{T}$)
* **Модель:** Двусторонняя бесконечная лента ячеек:
  $$\mathcal{T}: \mathbb{Z} \to \mathbb{Z}/256\mathbb{Z}$$
* **Инициализация:** $\forall i \in \mathbb{Z}: \mathcal{T}_0(i) = 0$.
* **Указатель данных ($P$):** Целочисленный индекс текущей активной ячейки: $P \in \mathbb{Z}$, $P_0 = 0$.
* **Ограниченный режим (Bounded Execution):** При флаге `--bounded N` адресное пространство сжимается до полуинтервала $[0, N-1]$. Попытка адресации $P < 0$ или $P \ge N$ инициирует немедленный останов по ошибке `E005`.

### 3.2. Счётчик инструкций ($PC$) и стек переходов ($\Sigma_{loop}$)
* $PC \in \mathbb{N}_0$ указывает на индекс текущей исполняемой атомарной команды в линейном массиве инструкций $\mathcal{C}$.
* $\Sigma_{loop}$ — стек типа LIFO, хранящий пары индексов начала и конца циклических участков для контроля вложенности.

### 3.3. Ввод/Вывод ($\mathcal{I}$, $\mathcal{O}$)
* $\mathcal{I}$ — входной поток 8-битных байтов: $\mathcal{I} \in (\mathbb{Z}/256\mathbb{Z})^*$.
* $\mathcal{O}$ — выходной поток 8-битных байтов: $\mathcal{O} \in (\mathbb{Z}/256\mathbb{Z})^*$.

## 4. Система команд (Instruction Set Architecture)

Из 27 форм алфавита 8 словоформ зарезервированы под операторы управления машиной в режиме `CODE`:

| Мнемоника | Словоформа | Код корня/формы | Формальная семантика (Предусловия и постусловия) |
| :--- | :--- | :---: | :--- |
| **INC** | `блядь` | `(0, 0)` | $\mathcal{T}_{t+1}(P_t) = (\mathcal{T}_t(P_t) + 1) \pmod{256}$ |
| **DEC** | `хуй` | `(1, 0)` | $\mathcal{T}_{t+1}(P_t) = (\mathcal{T}_t(P_t) - 1) \pmod{256}$ |
| **RIGHT** | `пизда` | `(2, 0)` | $P_{t+1} = P_t + 1$ |
| **LEFT** | `бляди` | `(0, 1)` | $P_{t+1} = P_t - 1$ |
| **OUT** | `хуя` | `(1, 1)` | $\mathcal{O}_{t+1} = \mathcal{O}_t \mathbin{\Vert} \mathcal{T}_t(P_t)$ |
| **IN** | `пизды` | `(2, 1)` | Если $\mathcal{I} \neq \emptyset$: $\mathcal{T}_{t+1}(P_t) = \text{head}(\mathcal{I})$, $\mathcal{I}_{t+1} = \text{tail}(\mathcal{I})$.<br>Если $\mathcal{I} = \emptyset$: $\mathcal{T}_{t+1}(P_t) = 0$ (при `--strict-eof` $\to$ `E006`). |
| **LOOP** | `блядью` | `(0, 2)` | Если $\mathcal{T}_t(P_t) = 0$, то $PC_{t+1} = \text{match}(PC_t) + 1$. |
| **END** | `пиздец` | `(2, 5)` | Если $\mathcal{T}_t(P_t) \neq 0$, то $PC_{t+1} = \text{match}(PC_t) + 1$. |

*Примечание:* Функция $\text{match}(k)$ возвращает индекс парной скобки, однозначно вычисленный на этапе статического семантического анализа.

Остальные 19 канонических словоформ делятся на мета-операторы переключения контекста (`блядство`, `хуёвина`, `пиздю`) и зарезервированные расширения спецификации.

## 5. Режимы исполнения и структура файлов

### 5.1. Режимы транслятора
1. **Режим исполнения (`CODE`):** Каждое слово транслируется в соответствующую инструкцию виртуальной машины.
2. **Режим данных (`DATA`):** Слова транслируются исключительно как цифры троичной системы счисления:
   $$\text{val}(w) = \begin{cases} 0, & w = \text{`блядь`} \\ 1, & w = \text{`хуй`} \\ 2, & w = \text{`пизда`} \end{cases}$$
   Использование любых других словоформ в режиме `DATA` влечет ошибку `E003`.

### 5.2. Типы файлов и расширения

#### A. Исполняемый файл программы (`.blyad`)
Содержит инструкции в режиме `CODE`. Не требует заголовка.

#### B. Файл данных (`.blyad-data`)
Содержит упакованную последовательность байтов.
Структура файла строго детерминирована:
```text
[МАГИЧЕСКИЙ_ПРЕАМБУЛ] [ДЛИНА_В_ТРИТАХ] [РАЗДЕЛИТЕЛЬ] [ПОЛЕЗНАЯ_НАГРУЗКА]
```
1. **Магический преамбул:** `блядство хуёвина пиздю`
2. **Длина полезной нагрузки ($N$ байт):** Произвольное число тритов из словаря режима `DATA`, задающее длину последующих данных в байтах.
3. **Разделитель длины:** Токен `пиздю`.
4. **Полезная нагрузка:** Ровно $6 \times N$ слов из словаря режима `DATA`.

#### C. Смешанный файл (`.blyad-mix`)
Позволяет встраивать неисполняемые блоки инициализации данных непосредственно в код программы.
* Маркер входа в блок данных: `блядство` (переключает парсер в режим `DATA`).
* Маркер выхода из блока данных: `хуёвина` (возвращает парсер в режим `CODE`).

**Семантика исполнения смешанного блока:**
Блок тритов преобразуется в массив байтов $\{B_0, B_1, \dots, B_{k-1}\}$. При достижении блока машиной происходит последовательная запись байтов на ленту начиная с текущей позиции указателя $P$, при этом после записи каждого байта указатель инкрементируется:
$$\forall j \in [0, k-1]: \mathcal{T}(P + j) \leftarrow B_j; \quad P \leftarrow P + k$$

## 6. Теория кодирования данных (Кодирование байтов)

### 6.1. Биекция байтового пространства в пространство тритов
Отображение байта в последовательность тритов определяется биективным отображением:
$$\Phi: \mathbb{Z}/256\mathbb{Z} \to \{0, 1, 2\}^6$$

Разложение байта $B \in [0, 255]$ осуществляется по полиномиальному троичному базису:
$$B = \sum_{i=0}^{5} t_i \cdot 3^{5-i} = t_0 \cdot 243 + t_1 \cdot 81 + t_2 \cdot 27 + t_3 \cdot 9 + t_4 \cdot 3 + t_5 \cdot 1$$
где $t_i \in \{0, 1, 2\}$, а $t_0$ является старшим тритом (Big-Endian).

### 6.2. Ограничения допустимости
Информационная ёмкость 6 тритов составляет:
$$3^6 = 729 \text{ состояний}$$
Множество допустимых кодовых последовательностей ограничивается условием:
$$\sum_{i=0}^{5} t_i \cdot 3^{5-i} \le 255$$
Значения в полуинтервале $[256, 728]$ являются запрещёнными дефектными состояниями и вызывают отказ исполнения `E003: ПИЗДЕЦ ДАННЫМ`.

### 6.3. Канонический пример
Кодирование ASCII-символа `'A'` (код $65_{10}$):
$$65 = 0 \cdot 243 + 0 \cdot 81 + 2 \cdot 27 + 1 \cdot 9 + 0 \cdot 3 + 2 \cdot 1 \implies (0, 0, 2, 1, 0, 2)_3$$

Трансляция в лексемы режима `DATA`:
$$\Phi(65) = \text{блядь} \quad \text{блядь} \quad \text{пизда} \quad \text{хуй} \quad \text{блядь} \quad \text{пизда}$$

## 7. Формальная грамматика (EBNF)

Ниже представлена формальная грамматика БЛЯДОКОДА 1.0 в нотации Бэкуса — Наура (Extended Backus-Naur Form):

```ebnf
(* Терминальные корни *)
ROOT_ZERO = "блядь" ;
ROOT_ONE  = "хуй" ;
ROOT_TWO  = "пизда" ;

(* Полный словарь допустимых токенов *)
TOKEN_0_0 = "блядь" ;    TOKEN_1_0 = "хуй" ;      TOKEN_2_0 = "пизда" ;
TOKEN_0_1 = "бляди" ;    TOKEN_1_1 = "хуя" ;      TOKEN_2_1 = "пизды" ;
TOKEN_0_2 = "блядью" ;   TOKEN_1_2 = "хую" ;      TOKEN_2_2 = "пизде" ;
TOKEN_0_3 = "блядей" ;   TOKEN_1_3 = "хуем" ;     TOKEN_2_3 = "пизду" ;
TOKEN_0_4 = "блядям" ;   TOKEN_1_4 = "хуе" ;      TOKEN_2_4 = "пиздой" ;
TOKEN_0_5 = "блядями" ;  TOKEN_1_5 = "хуи" ;      TOKEN_2_5 = "пиздец" ;
TOKEN_0_6 = "блядях" ;   TOKEN_1_6 = "хуёв" ;     TOKEN_2_6 = "пиздеть" ;
TOKEN_0_7 = "блядская" ; TOKEN_1_7 = "хуёвый" ;   TOKEN_2_7 = "пиздёж" ;
TOKEN_0_8 = "блядство" ; TOKEN_1_8 = "хуёвина" ;  TOKEN_2_8 = "пиздю" ;

TRIT_TOKEN = ROOT_ZERO | ROOT_ONE | ROOT_TWO ;

(* Инструкции виртуальной машины *)
INSTR_INC   = TOKEN_0_0 ;
INSTR_DEC   = TOKEN_1_0 ;
INSTR_RIGHT = TOKEN_2_0 ;
INSTR_LEFT  = TOKEN_0_1 ;
INSTR_OUT   = TOKEN_1_1 ;
INSTR_IN    = TOKEN_2_1 ;
INSTR_LOOP  = TOKEN_0_2 ;
INSTR_END   = TOKEN_2_5 ;

INSTRUCTION = INSTR_INC | INSTR_DEC | INSTR_RIGHT | INSTR_LEFT
            | INSTR_OUT | INSTR_IN | LOOP_BLOCK ;

LOOP_BLOCK  = INSTR_LOOP , { INSTRUCTION | MIXED_DATA_BLOCK } , INSTR_END ;

(* Смешанные структуры *)
DATA_OPEN        = TOKEN_0_8 ; (* блядство *)
DATA_CLOSE       = TOKEN_1_8 ; (* хуёвина *)
DATA_LENGTH_DELIM= TOKEN_2_8 ; (* пиздю *)

ENCODED_BYTE     = TRIT_TOKEN , TRIT_TOKEN , TRIT_TOKEN , TRIT_TOKEN , TRIT_TOKEN , TRIT_TOKEN ;
MIXED_DATA_BLOCK = DATA_OPEN , { ENCODED_BYTE } , DATA_CLOSE ;

(* Грамматики конкретных типов файлов *)
BLYAD_PROGRAM    = { INSTRUCTION } ;
BLYAD_MIX_PROGRAM= { INSTRUCTION | MIXED_DATA_BLOCK } ;

DATA_FILE_HEADER = DATA_OPEN , DATA_CLOSE , DATA_LENGTH_DELIM ;
DATA_FILE_LENGTH = { TRIT_TOKEN } , DATA_LENGTH_DELIM ;
BLYAD_DATA_FILE  = DATA_FILE_HEADER , DATA_FILE_LENGTH , { ENCODED_BYTE } ;
```

## 8. Спецификация системы исключений и прерываний

При возникновении фатальных ситуаций исполнение немедленно прекращается. Система возвращает ненулевой код возврата и генерирует диагностическое сообщение:

```text
[КОД_ОШИБКИ] НАЗВАНИЕ: Описание причины с указанием строки
```

| Код | Нормативное наименование | Условие возбуждения (Invariant Violation) |
| :---: | :--- | :--- |
| **E001** | `БЛЯДЬ НЕ РАСПОЗНАНА` | Входной токен $w \notin \mathbf{M}_{\text{Lex}}$ (за пределами 27 слов). |
| **E002** | `ХУЙНЯ С ЦИКЛОМ` | Нарушение гомеоморфизма скобочной структуры `LOOP` / `END`: стек $\Sigma_{loop}$ пуст при встрече `пиздец`, либо не пуст по достижении конца файла. |
| **E003** | `ПИЗДЕЦ ДАННЫМ` | Число тритов в блоке $\not\equiv 0 \pmod 6$, либо значение шестёрки тритов $> 255$, либо дефектная длина файла данных. |
| **E004** | `БЛЯДСКИЙ РЕЖИМ` | Некорректное состояние конечного автомата режимов: попытка вложения `блядство` внутри блока данных, либо появление `хуёвина` вне блока данных. |
| **E005** | `ХУЙ ЗНАЕТ ГДЕ УКАЗАТЕЛЬ` | Нарушение барьера ограниченной ленты: $P_t < 0 \lor P_t \ge N$ при заданном параметре `--bounded N`. |
| **E006** | `ПИЗДЕЦ ВВОДУ` | Чтение из исчерпанного входного потока ($\mathcal{I} = \emptyset$) при установленном флаге строгой валидации `--strict-eof`. |

## 9. Доказательство Тьюринг-полноты

**Теорема 9.1.** *Язык БЛЯДОКОД вычислительно полон по Тьюрингу.*

*Доказательство.*  
Доказательство проведём путём построения сюръективного гомоморфизма языков:

$$\Psi: \text{Blyadokod} \to \text{Brainfuck}$$

Определим точечное отображение для операторов ядра Brainfuck:

| БЛЯДОКОД | Brainfuck | Семантика |
| :--- | :---: | :--- |
| `блядь` | `+` | Инкремент ячейки |
| `хуй` | `-` | Декремент ячейки |
| `пизда` | `>` | Сдвиг указателя вправо |
| `бляди` | `<` | Сдвиг указателя влево |
| `хуя` | `.` | Вывод байта |
| `пизды` | `,` | Ввод байта |
| `блядью` | `[` | Начало цикла |
| `пиздец` | `]` | Конец цикла |

Отображение $\Psi$ сохраняет топологию переходов циклов, свойства коммутативности сдвигов указателя и ассоциативность модификации ячеек по модулю 256. 

Поскольку классический язык Brainfuck при бесконечной ленте и байтовых ячейках Тьюринг-полон (Böhm-Jacopini theorem, редукция к машине Минского с двумя счётчиками), редуцируемый к нему БЛЯДОКОД также вычислительно универсален по Тьюрингу. $\blacksquare$
